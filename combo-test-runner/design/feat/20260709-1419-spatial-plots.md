# Feature: spatial plots + GIF per combination

## Goal

Render a **spatial map for every NetCDF file** each combination produces,
plus an **animated GIF per variable** stringing those maps together, written
to a `plots/` subfolder of each combo directory. Plotting mirrors the
capabilities of `cece-data-viewer/app/analysis.py` (`render_spatial_plot`,
`compute_scale`, `render_gif`): cartopy PlateCarree maps, viridis pcolormesh,
coastlines and country borders, colorbar with units, and a footer note. The
color scale for a variable is **shared across every plot in the suite run**,
so maps are visually comparable across combos and timesteps.

## Design

### `plotting` block in the suite config

```yaml
plotting:
  enabled: true       # default; false disables plots and GIFs entirely
  gif_enabled: true   # default; false renders PNGs but no GIFs
```

```python
class Plotting(StrictModel):
    enabled: bool = True
    gif_enabled: bool = True

class SuiteConfig(StrictModel):
    ...
    plotting: Plotting = Plotting()   # section optional; defaults apply
```

(The raw note sketched a `suite:` wrapper; `plotting` sits at the top level
of the suite yaml like `assertions` and `analysis`.) The block lands in
`run.yaml` automatically via the embedded resolved suite.

### Why rendering happens at session end, not in a per-combo test

The shared scale is the forcing constraint: a variable's color range is the
2nd/98th percentile of its values **across all NetCDFs of all combos**
(mirroring `compute_scale`, widened suite-wide), which cannot be known until
every driver run has finished. So plotting runs in **`pytest_sessionfinish`**
(alongside the stats-CSV concatenation, after it):

1. Scan every combo directory for `*.nc`.
2. Per variable: compute the suite-wide `(vmin, vmax)` percentile scale
   (guarded: if `vmin == vmax`, expand so matplotlib gets a valid range).
3. Per combo, per NetCDF, per data variable: render one PNG into
   `<combo-dir>/plots/`.
4. Per combo, per variable (when `gif_enabled`): assemble the PNGs in
   filename order (timestamp order) into `<combo-dir>/plots/<variable>.gif`
   (adaptive palette, ~400 ms/frame, infinite loop — per the guide).

Two consequences, stated deliberately:

- **Plot failures are not test failures.** Plots are diagnostic artifacts,
  not assertions; exceptions during rendering are logged at ERROR and skip
  the affected plot rather than failing the session. (A future plot-count
  assertion can revisit this.)
- **No dask client**: session fixtures (including `dask_client`) are torn
  down before `sessionfinish`; scale scanning and rendering use plain
  xarray/numpy, which is fine at these data sizes.

### Rendering (`src/plotting.py`, mirroring the guide)

- `matplotlib.use("Agg")`; PlateCarree projection, `pcolormesh` with
  `viridis`, colorbar labeled `<variable> [units]` (units from attrs,
  `[unknown]` fallback).
- **Geographic boundaries** as in the guide: coastlines plus
  `cfeature.BORDERS`, each wrapped in try/except with a WARNING log —
  cartopy fetches Natural Earth data on first use, and an offline machine
  degrades to a data-only map instead of erroring. Axis ticks use the
  Longitude/LatitudeFormatter workaround (not `draw_labels=True`), same
  cartopy/shapely rationale as the guide.
- Title: `<variable>  <time label>` (time from the file's time coordinate,
  as in the stats columns).
- **Footer, lower right**:
  `Generated by CECE combo-test-runner <UTC ISO-8601 timestamp>` — small
  gray text via `fig.text`, replacing the guide's `generated <ts>` note.
- Per-variable scale passed in from the suite-wide computation; a
  `VariableScale` frozen pydantic model (`variable`, `vmin`, `vmax`) keeps
  the registry typed.
- Plot filename: `<variable>__<nc-stem>.png` (e.g.
  `co__cece_20100101_010000.png`); one plot per (file, variable), first
  timestep/level when a file carries more than one (multi-timestep files
  don't occur with current driver output; level selection is future work).

### Dependencies

`matplotlib`, `cartopy`, `pillow` join the project dependencies — the
plotting third of the guide's stack (numpy/xarray/pandas already present).

## Ripples (standing process rules)

- **Harness tests** (fabricated NetCDFs, no docker): PNG rendered per
  (file, variable) with nonzero size; GIF assembled from ≥2 frames;
  suite-wide scale matches numpy 2nd/98th percentiles across multiple files
  and equals across combos; the `vmin == vmax` guard; `enabled: false`
  writes nothing; `gif_enabled: false` writes PNGs but no GIF; `Plotting`
  defaults and unknown-key rejection.
- **`design.md`**: directory layout gains `plots/`; code layout gains
  `plotting.py`; dependency list; suite example gains the block.
- **`README.md`**: results layout, suite option description, note that
  first-time cartopy boundary rendering downloads Natural Earth data.
- Pydantic models, never dataclasses.

## Non-goals

- No diff plots, temporal line plots, or metadata dumps from the guide.
- No per-level plot selection (`lev` beyond the first level) and no
  plot-based assertions — artifacts only, this iteration.
- No plot styling configuration in the suite beyond the two booleans.

## Acceptance criteria

- Integration (defaults): every combo directory gains `plots/` with one PNG
  per NetCDF × variable and one `<variable>.gif`; all PNGs of a variable
  share one color range; each PNG carries the footer text.
- `plotting.enabled: false` → no `plots/` directories; `gif_enabled: false`
  → PNGs without GIFs.
- Rendering problems (e.g. missing boundary data offline) degrade with
  WARNING/ERROR logs; the session outcome is unchanged.
- Harness passes without docker; integration keeps its shape (now fully
  green after the driver stamp fix).
